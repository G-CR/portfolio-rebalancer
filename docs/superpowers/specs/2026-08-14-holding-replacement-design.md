# 持仓标的替换设计

## 背景与目标

用户已在券商账户中全部卖出 SPY，并买入同属“标普 500”资产类别的 VOO。当前前端只能分别执行卖出调整、归档旧持仓和新增持仓，没有集中入口；后端虽然允许修改持仓身份字段，但直接把 SPY 重命名为 VOO 会错误地改写成本历史和当前持仓身份。

本功能提供“替换标的”引导操作，在一个原子事务中完成：

1. 将来源持仓全部卖出至零份额；
2. 保留卖出调整记录并归档来源持仓；
3. 创建目标持仓；
4. 将目标持仓设为所属资产类别的默认调整标的。

首个使用场景为 SPY → VOO，但能力应适用于任意有效持仓间的完整替换，不在代码中写死具体代码。

## 非目标

- 不把来源持仓直接重命名为目标持仓。
- 不计算或展示已实现盈亏、成交收入、税费或资金流水。
- 不支持部分卖出后替换；来源持仓必须被全部归零并归档。
- 不修改历史快照。旧快照继续保留当时记录的 SPY，新快照反映 VOO。
- 不自动向券商下单，也不从券商同步成交。
- 不在第一版增加交易日期回填或历史调整日期编辑能力。

## 用户流程

### 入口

有效且份额大于零的持仓，在行末“更多操作”菜单中显示“替换标的”。用户从 SPY 行进入后，打开替换抽屉。

零份额、已归档持仓不显示该入口。现有的卖出调整、人工修正、调整历史和归档操作保持不变。

### 表单

抽屉标题为“替换标的 · SPY”，顶部说明：来源持仓将全部归零并归档，历史记录不会被改写。

来源区域只读展示：

- 来源代码与名称；
- 所属资产类别；
- 当前账户；
- 将被卖出的全部份额。

目标区域允许填写：

- 目标代码，必填，例如 `VOO`；
- 目标名称，必填，例如 `Vanguard S&P 500 ETF`；
- 实际买入后的份额，必填且大于零；
- 平均成本价，必填且非负；
- 成本汇率，非 CNY 持仓必填且大于零；
- 基准汇率，非 CNY 持仓必填且大于零；
- 备注，可选，用于来源持仓的全部卖出调整记录。

以下目标属性默认继承来源持仓，并允许在高级设置中修改：

- 账户名称；
- 上市市场；
- 交易币种；
- 最小交易单位；
- 份额小数位；
- 首选行情来源。

目标持仓固定属于来源持仓的资产类别，并固定成为该类别的默认调整标的，不在表单中提供关闭选项。

### 预览与确认

提交按钮上方展示结果摘要：

- SPY：全部卖出、份额归零、归档；
- VOO：创建到“标普 500”，成为默认调整标的；
- 历史快照与既有调整记录保持不变；
- 系统不会计算 SPY 已实现盈亏。

主按钮使用结果导向文案“确认替换为 VOO”。提交期间禁用关闭和重复提交。

成功后关闭抽屉并显示成功反馈。持仓列表应只显示新的 VOO；若用户选择查看归档持仓，仍能看到份额为零的 SPY。

## 后端接口

新增：

```text
POST /api/holdings/{source_holding_id}/replace
```

请求体：

```json
{
  "source_version": 3,
  "symbol": "VOO",
  "name": "Vanguard S&P 500 ETF",
  "account_name": "美股账户",
  "market": "US",
  "trade_currency": "USD",
  "quantity": "10",
  "average_cost_price": "625.40",
  "cost_fx_to_cny": "7.18",
  "baseline_fx_to_cny": "7.15",
  "lot_size": "1",
  "quantity_precision": 0,
  "preferred_data_source": null,
  "note": "全部卖出 SPY 后换入 VOO"
}
```

响应体同时返回归档后的来源持仓与新目标持仓，便于前端确认最终状态：

```json
{
  "source": {},
  "target": {}
}
```

为保持边界清晰，新增独立的替换请求与响应 schema；不复用允许可选字段的普通 `HoldingUpdate`。

## 事务与数据流

替换服务在单个数据库事务中完成以下步骤：

1. 按现有持仓写操作的统一顺序锁定有效资产类别。
2. 使用行锁读取来源持仓，并确认其仍有效且份额大于零。
3. 锁定来源资产类别下的有效持仓，防止默认调整标的并发冲突。
4. 校验目标 `symbol + account_name` 不与另一条有效持仓重复。
5. 按现有成本调整模型为来源持仓写入 `sell` 操作，卖出数量等于事务内重新读取的全部份额；卖出后份额为零，平均成本价和成本汇率保持现有卖出语义。
6. 将来源持仓标记为非默认调整标的并归档。
7. 创建目标持仓，使用请求中的实际买入后成本状态，并将其设为默认调整标的。
8. 再次执行该资产类别的默认持仓不变量检查并提交事务。

任何校验、唯一约束或数据库写入失败都回滚整个事务。不会出现来源 SPY 已归档但目标 VOO 未创建的中间状态。

来源持仓调整记录使用已有 `CostAdjustment` 表，记录操作前后状态、替换请求摘要和可选备注。目标持仓的初始成本状态直接写入新持仓；第一版不额外创建一条“买入”调整记录，保持与当前“新增持仓”语义一致。

## 校验与错误处理

后端返回结构化错误，前端展示中文安全文案并保留表单输入：

| 场景 | 状态码 | 错误代码 | 行为 |
| --- | --- | --- | --- |
| 来源不存在或已归档 | 404 | `HOLDING_NOT_FOUND` | 不创建目标持仓 |
| 来源份额已为零 | 409 | `HOLDING_REPLACEMENT_SOURCE_EMPTY` | 提示改用归档操作 |
| 目标代码和账户已存在 | 409 | `HOLDING_ALREADY_EXISTS` | 提示选择已有持仓或更改账户 |
| 目标份额不大于零 | 422 | `HOLDING_REPLACEMENT_QUANTITY_INVALID` | 标记目标份额字段 |
| 市场、币种、精度或成本非法 | 422 | 沿用现有结构化校验代码 | 标记对应字段 |
| 并发修改来源持仓 | 409 | `HOLDING_VERSION_CONFLICT` | 重新加载来源状态后重试 |

请求包含来源持仓 `version`，后端在锁定后进行乐观版本校验，避免用户打开抽屉后来源份额已发生变化，却仍按旧预览执行全部卖出。

提交失败时抽屉保持打开，用户输入不被清空。成功响应返回前，不在前端乐观隐藏 SPY 或插入 VOO。

## 前端数据更新

新增替换 mutation。成功后使以下查询失效并重新获取：

- 有效及含归档的持仓列表；
- 来源持仓的成本调整历史；
- 行情数据列表；
- 组合分析与仪表盘；
- 再平衡预览、方案和输入缺失状态；
- 快照列表及相关摘要。

目标 VOO 没有有效行情时，沿用现有持仓页缺失行情检测与自动刷新机制。替换接口自身不调用外部行情供应商，避免将外部网络失败纳入数据库事务。

## 可访问性与交互细节

- 菜单项和抽屉标题包含来源代码，便于读屏识别。
- 所有字段具有可访问标签；错误与具体字段关联。
- 抽屉遵循现有焦点圈定、Escape 关闭和关闭后焦点归还规则。
- 提交期间按钮显示“正在替换”，并阻止重复提交。
- 高风险结果使用明确文字，不仅依赖颜色或图标表达。

## 测试策略

### 后端集成测试

- SPY 全部替换为 VOO 的成功路径。
- 来源 SPY 归零、归档并保留平均成本语义。
- 生成完整卖出调整记录。
- VOO 继承资产类别并成为唯一默认调整标的。
- 同账户已有 VOO 时返回冲突且 SPY 保持不变。
- 来源已归档、份额为零、版本过期时拒绝请求。
- 非法份额、市场、币种、汇率、精度时拒绝请求。
- 创建目标过程中发生异常时验证整个事务回滚。
- 并发替换或并发修改时不破坏唯一默认标的不变量。

### 前端组件测试

- 仅有效且非零持仓显示“替换标的”入口。
- 表单正确继承来源持仓默认值。
- 预览明确显示来源归档、目标创建及不计算已实现盈亏。
- 请求体包含来源版本和完整目标成本状态。
- 提交期间防止重复操作。
- 后端错误显示后保留输入并允许重试。
- 成功后关闭抽屉、反馈成功并触发所需查询失效。

### 端到端测试

- 从 SPY 行进入替换抽屉，录入 VOO，确认后持仓页显示 VOO、不再显示有效 SPY。
- 查看归档持仓时可以找到零份额 SPY。
- 再平衡页面使用 VOO 作为“标普 500”的默认交易标的。

## 验收标准

1. 用户可以从现有 SPY 持仓一次完成完整替换为 VOO。
2. 操作具有事务原子性，失败时不会留下半完成状态。
3. 历史快照和历史成本调整记录不被改写。
4. 替换后 VOO 是“标普 500”唯一默认调整标的。
5. 系统明确说明并继续遵守“不计算已实现盈亏”的现有产品口径。
6. 目标行情获取失败不影响替换事务，页面通过现有行情状态和重试能力处理。
