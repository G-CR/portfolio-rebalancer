# 再平衡测算跨页面恢复设计

## 现状与目标

测算已经由数据库任务和 worker 在后台执行。再平衡页面将任务 ID、轮询和结果保存在组件状态；切换路由后组件卸载，返回时无法找回任务。未保存的测算结果虽然留在任务表中，页面目前只恢复进行中的正式方案。

用户进入再平衡页面时，应自动找回最近一次手动测算：排队、刷新行情或计算中的任务继续显示进度；成功任务显示结果；失败任务显示原因。页面切换、刷新浏览器和 API 重启后都使用数据库任务作为恢复依据。点击下一次测算后，以新任务取代旧任务。

## 数据与接口

复用 `rebalance_preview_jobs`，不新增表。`GET /api/rebalance/preview-jobs/latest` 返回按创建时间与 ID 排序的最新任务，若从未测算则返回 `null`。任务响应增加已验证的输入快照、创建/完成时间，以及成功结果是否仍与当前持仓、资产目标和有效行情一致。已有按 ID 查询和创建接口继续可用。

成功结果保存一个输入签名：按稳定顺序散列持仓版本、资产目标、每项有效行情的值、状态、来源及币种。读取成功任务时，用当前数据库输入重新计算签名；旧任务没有签名时视为不可直接用于正式方案。输入快照还用于恢复页面资金、容差、估值口径及卖出/换汇选项。

## 页面行为

- 首次进入时载入最新任务和默认配置；有任务时用该任务的输入快照恢复表单。
- 任务进行中时按现有频率轮询；完成后直接显示结果，失败时显示错误并允许重新测算。
- 结果可以一直作为上次测算展示。若输入签名不匹配，显示“上次测算，仅供参考”，禁用保存与开始，直到再次测算成功。
- 表单参数改动沿用现有“需要重新测算”规则。顶部手动刷新行情后重新检查结果是否仍有效。
- 正式方案保存请求带上测算输入签名。服务端在保存前重新核对；若输入已变化，返回明确冲突错误，阻止把旧结果保存为新方案。保存成功后页面展示实际保存的方案结果。

## 边界与验证

只恢复最近一项手动测算；正式方案的进行中恢复优先，历史草稿不混入测算结果。此应用当前以单用户部署，任务不按浏览器隔离。测试覆盖无任务、后台任务跨页面继续、成功结果回显、参数恢复、旧输入阻止保存、再次测算替换旧结果及已有正式方案流程。部署更新 API、worker 与前端，不修改数据库结构或现有数据卷。
