# 移除手填成本汇率与汇率盈亏归因

日期：2026-11-04
状态：已实施

## 背景

此前每个非人民币持仓都要求用户填写“成本汇率”和“基准汇率”。系统用它们计算人民币成本、价格影响、汇率影响和剔汇率占比。用户实际无法追溯真实换汇成本，手填值只是估算，导致人民币盈亏和再平衡口径同时失真。

## 决策

- 原币损益为主口径：交易币种的成本、市值、浮动盈亏和收益率只由份额、平均成本价和当前价计算。
- 人民币为参考口径：人民币成本、市值和盈亏按当前汇率折算，用于跨币种汇总和配置比例，不宣称是真实换汇损益。
- 删除所有由手填成本汇率派生的字段和页面：`cost_fx_to_cny`、`baseline_fx_to_cny`、`fx_neutral_*`、`price_effect`、`fx_effect`、`fx_contribution`、再平衡 `valuation_basis` / `fx_comparison`。
- 保留当前汇率行情、手动覆盖、数据状态、再平衡换汇能力（`allow_fx`、净换汇字段）和海外资产占比。
- 跨币种费用按服务端当前有效汇率自动折算；缺失时若费用币种为 CNY 则明确报错。

本决策取代 `2026-09-30-long-term-ledger-design.md` 中“保留基准汇率用于剔汇率比较”的表述。该文其余关于参考汇率和原币损益的原则继续有效。

## 数据与兼容

- 新增 Alembic 迁移 `20261104_0012`：先用快照自身保存的 `current_fx_to_cny` 重算 `cost_value_cny`、`unrealized_pnl_amount_cny` 和 `unrealized_pnl_rate`；`current_fx_to_cny` 为空的历史行没有有效参考成本，三项一并置 `NULL`；最后删除相关列。
- 逻辑备份格式升级到 v3。v1 是原始格式，v2 是已部署过的账本/提醒格式；两者都可恢复。v2 的账本与提醒成员会被逐字节校验后明确忽略，并在恢复预览中给出警告。
- v1/v2→v3 的行级转换会删除成本汇率相关列、重算快照参考成本/盈亏、清理再平衡 JSON 中的 `valuation_basis` 和 `fx_comparison`。
- 旧的再平衡方案记录保留 JSON 原样，但读取时只暴露新字段；`strategy_mode` 与 `baseline_reset_at` 列删除。

## 验证

- 后端：分析域、成本引擎、持仓/成本调整 API、快照、再平衡、设置、邮件、备份导出/校验/恢复、Alembic 升级/降级。
- 前端：总览、盈亏页、持仓表与抽屉、快照、再平衡、设置；删除价格/汇率拆分图表和剔汇率交互。
- 关键不变量：人民币浮动盈亏 = 人民币市值 − 人民币参考成本；原币浮动盈亏与当前汇率无关。
