# 后台再平衡预览任务设计

## 背景

当前再平衡预览接口在一次 HTTP 请求中依次刷新行情、执行两种汇率口径下的离散优化并返回结果。新增多个标的后，行情获取与整数规划的组合执行时间超过前端代理的 60 秒读取超时，导致用户看到 504；同步优化还会占满 API 进程，影响健康检查和其他页面请求。

本设计将预览计算从 API 请求移入现有 worker 容器。目标是使 API 始终快速响应，并让网页自动展示后台进度和最终结果。

## 目标与非目标

目标：

- 点击“开始测算”后立即得到可轮询的任务标识，而不等待行情或优化结束。
- 页面自动显示刷新与计算状态，并在成功后自动显示建议结果。
- 行情缺失、需要确认旧行情、优化未能在时间预算内完成，都以明确的业务失败结果呈现，而不是网关 504。
- API 或 worker 重启后，未完成任务可恢复处理；持仓、设置及历史方案不被任务机制修改。
- 保持现有可认证离散优化语义；增加明确的执行时间上限，防止无限占用 CPU。

非目标：

- 不改变资产配置、持仓、容差、交易单位或行情源优先级。
- 不接入券商、不自动下单。
- 不改造正式方案的保存、开始、取消或完成生命周期。
- 不以降低 Nginx 超时作为解决方案。

## 方案比较

1. 在同步预览上增加更短超时：改动最小，但仍会占用 API，并且无法显示真实进度。
2. 持久化后台预览任务：API 快速返回，worker 执行耗时工作，网页轮询展示状态。实现范围适中且可恢复，采用本方案。
3. 将优化改为启发式：可能更快，但会放弃目前的可认证最优保证，不采用。

## 数据模型

新增 `rebalance_preview_jobs` 表，保存：

- `id`：任务 UUID。
- `status`：`queued`、`refreshing`、`calculating`、`succeeded`、`failed`。
- `payload`：一次预览所需的已验证输入快照，包括资金、容差、卖出/换汇开关、估值口径、旧行情确认和会话令牌。
- `result`：成功时的完整预览响应快照。
- `error`：失败时的安全业务错误（状态码、代码、消息、详情）。
- `created_at`、`started_at`、`heartbeat_at`、`finished_at`：领取、恢复与展示进度所需时间戳。

API 创建任务使用请求令牌作为幂等键：同一请求重复提交返回同一个任务，避免重复刷新和重复计算。worker 启动时将超过恢复阈值且仍处于执行状态的任务重新放回队列。

## API 与数据流

1. `POST /api/rebalance/preview-jobs` 验证输入、创建或复用排队任务，并返回 `202 Accepted` 与任务状态。
2. `GET /api/rebalance/preview-jobs/{id}` 返回最新状态、成功结果或业务失败信息。
3. 前端在创建后每秒轮询该 GET 接口；`queued`、`refreshing`、`calculating` 显示加载状态；终态停止轮询。
4. worker 以数据库锁领取一个排队任务，写入 `refreshing`，完成行情刷新后写入 `calculating`，最终保存 `succeeded` 或 `failed`。
5. 页面在成功时将结果写入现有预览状态；失败时沿用现有错误提示区域显示任务返回的业务错误。
6. 保存正式方案仅使用已经成功取得的预览结果，继续走现有保存接口和版本校验。

## 行情与优化边界

worker 中的行情刷新不再受网页请求超时约束。刷新完成后，若必需行情缺失，任务以 `REBALANCE_DATA_INCOMPLETE` 结束；若只有旧行情且未确认，任务以 `REBALANCE_STALE_DATA_ACK_REQUIRED` 结束。

离散优化保留现有认证逻辑，并在节点搜索循环中检查单调时钟截止时间。到期时抛出新的可序列化优化超时错误；worker 将其记录为业务失败而非进程异常。计算在 worker 容器中运行，故不会阻塞 API 健康检查。

## 并发、恢复与安全

- 一个 worker 实例一次领取一个任务；领取使用行锁，避免重复执行。
- 任何 API 重启不影响已存储的任务与结果。
- worker 重启时，超出心跳恢复阈值的 `refreshing` 或 `calculating` 任务会回到 `queued`；已经成功或失败的任务永不重复执行。
- 任务只读取持仓和设置、刷新市场数据并保存任务自身状态；不写入持仓、资产类别或再平衡方案。
- 返回给前端的错误沿用现有安全错误码和详情格式，不保存 provider 凭据或原始异常文本。

## 前端体验

- “开始测算”按钮提交任务后禁用重复提交。
- 结果区域显示“正在排队”“正在刷新行情”或“正在计算方案”。
- 成功后无需手动刷新，直接渲染现有汇总、目标占比、交易建议与汇率对照。
- 任务失败后停止轮询，恢复按钮可用，并显示可行动的中文错误信息。

## 测试策略

- 后端 API：创建任务的幂等性、查询各状态、成功结果和业务失败结果。
- worker：领取任务、状态顺序、刷新/计算成功、行情不完整、优化超时，以及过期执行任务的恢复。
- 优化器：指定时间预算时能产生确定性的超时错误，未超时时继续返回认证结果。
- 前端：创建后轮询、三种进行中状态、成功自动渲染、失败停止轮询并展示错误。
- 回归：现有同步方案保存、生命周期和行情接口测试保持通过。

## 验收标准

- 再平衡页面不会因为慢行情或复杂优化返回 504。
- API 在预览任务运行期间继续通过健康检查并能响应其他页面请求。
- 用户无需刷新页面即可看到最终结果或可理解的失败原因。
- worker 或 API 重启后，未完成任务不会永久卡在执行中。
- 修复期间及自动化测试均不访问或修改正式 Docker 数据卷。
