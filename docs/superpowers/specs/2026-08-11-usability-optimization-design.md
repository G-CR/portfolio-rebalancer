# 易用性优化设计

## 目标

在不增加首次使用引导、也不改变后端数据模型的前提下，降低日常维护组合时的认知负担：行情刷新状态可信，持仓录入按常见场景收敛，总览先给出行动结论，再平衡过程可按步骤执行。

## 范围与约束

- 顶栏刷新仅调用现有 `POST /api/market-data/refresh`，因此只刷新当前组合必需的行情和汇率。
- 不新增首次使用引导、导入功能、全局状态中心或后端 API。
- 持仓市场与现有后端约束一致：`US`、`SH`、`SZ`；交易币种仍仅支持 `CNY`、`USD`。
- 已存在的市场数据失败回退、手动覆盖和查询缓存失效机制必须保留。
- 再平衡始终不向券商提交订单。

## 方案

### 1. 顶栏行情刷新与状态

`AppShell` 复用现有市场数据查询和刷新 mutation。顶栏不再显示固定的“尚未刷新”：

- 有市场数据时，按数据集合计算最新的市场时间，并显示数据状态：有效、已过期或包含手动覆盖。
- 刷新期间，按钮禁用并显示“正在刷新”。
- 刷新完成后，统一失效总览、持仓、市场数据、再平衡和快照相关查询键，让当前页面显示新数据。
- 刷新请求失败时，保留既有数据和状态；按钮恢复可用，并显示到“数据源”页的可访问错误提示入口。

### 2. 持仓录入渐进展开

新增持仓抽屉优先展示用户必须填写的身份与成本字段。

- 市场使用选择框：美股（`US`）、上海 A 股（`SH`）、深圳 A 股（`SZ`）。选择市场自动设置默认币种：美股为 `USD`，A 股为 `CNY`。
- A 股的成本汇率和基准汇率固定为 `1`，不渲染为可编辑字段；美股继续显示两项汇率字段。
- 首选行情来源、最小交易单位、份额小数位和默认调整标的移动到可折叠的“高级设置”。其默认值和提交 payload 不变。
- 字段错误信息保持在抽屉内，关闭抽屉仍按现有行为清除会话。

### 3. 总览行动优先

复用现有 `decision` 数据，不扩展分析 API。

- “当前行动判断”保留在首屏，突出行动标题、原因和下一步按钮。
- 最大偏离与汇率贡献只在有实际行动需求时显示为辅助事实；保持现有再平衡链接文案与状态分支。
- 资产配置校准、盈亏拆分和数据状态仍完整展示，避免隐藏个人日常复核所需的数据。

### 4. 再平衡执行清单

在方案进入 `in_progress` 后，在生命周期区域展示固定四步清单：按建议交易、更新系统持仓、核对调整结果、完成并建立新基准。

- 清单明确标示“系统不会向券商提交订单”。
- 完成动作旁说明其副作用：创建调整后快照、把当前汇率设为新基准、不修改成本价或成本汇率。
- `draft`、`completed`、`cancelled` 的现有按钮状态和文案保持不变。

## 数据流与错误处理

刷新继续由市场数据 mutation 调用 API。成功响应触发 React Query 缓存失效；失败由 mutation 错误状态承载，不覆盖缓存中的旧行情。顶栏状态由已缓存的市场数据列表推导，不持久化额外客户端状态。

持仓市场选择只改变前端默认值与字段可见性；后端仍负责请求校验。再平衡清单完全由现有计划状态渲染，不新增服务器状态或工作流迁移。

## 测试

- 为顶栏新增测试：成功刷新调用现有接口、失效相关查询、展示请求中和失败状态。
- 为持仓抽屉新增测试：市场选择预设币种、A 股隐藏汇率、美股显示汇率、高级设置保留默认提交值。
- 为行动横幅新增测试：不同决策状态下的主要行动与辅助事实。
- 为再平衡生命周期新增测试：仅进行中的方案显示执行清单和完成副作用说明。

## 非目标

- 不增加首次使用向导、CSV 导入、券商连接、推送通知或用户账户。
- 不修改市场数据刷新算法、行情供应商顺序、再平衡数学模型或数据库迁移。
