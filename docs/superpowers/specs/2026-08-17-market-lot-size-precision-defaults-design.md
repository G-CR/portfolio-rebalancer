# 持仓市场默认交易单位与份额精度设计

## 背景

正式数据库中的 A 股 ETF `563020` 被记录为 `lot_size=1`、`quantity_precision=100`。持仓列表响应会按 `quantity_precision` 格式化数量；将 `15000` 量化为 100 位小数超过当前 Decimal 上下文精度，触发 `decimal.InvalidOperation`，导致 `/api/holdings?include_archived=true` 返回 500。资产配置页需要持仓列表计算每个资产类别的持仓影响，因此也被连带阻断。

当前创建和编辑持仓只校验份额小数位为非负整数，没有限制上限；前端也没有按市场填充合理默认值。这使本应填写在“最小交易单位”的 `100` 能被误填并持久化为“份额小数位”。

## 目标

- 按现有市场自动提供合理的最小交易单位与份额小数位默认值。
- 自动填充后仍允许用户手动修改。
- 在前后端阻止无效精度和非正最小交易单位进入数据库。
- 修复当前 `563020` 持仓，使持仓接口和资产配置页恢复正常。
- 保持正式数据卷、持仓数量、成本和汇率不变。

## 非目标

- 本次不新增港股市场或 HKD 支持。
- 不强制所有持仓始终使用市场默认值。
- 不新增数据库迁移或批量改写历史持仓。
- 不修改资产类别、行情、成本计算或再平衡规则。

## 市场默认规则

| 市场 | 交易币种 | 最小交易单位 | 份额小数位 |
| --- | --- | ---: | ---: |
| 美股 `US` | `USD` | `0.01` | `2` |
| 上海 A 股 `SH` | `CNY` | `100` | `0` |
| 深圳 A 股 `SZ` | `CNY` | `100` | `0` |

添加持仓时，每次选择或切换市场都把“最小交易单位”和“份额小数位”更新为该市场的默认值。用户可以在自动填充后继续编辑这两个字段；提交合法自定义值时，后端不得覆盖。

## 前端行为

`AddHoldingDrawer` 继续使用现有市场选择器和高级设置区域：

- 选择 `US` 时设置 `lot_size="0.01"`、`quantity_precision="2"`。
- 选择 `SH` 或 `SZ` 时设置 `lot_size="100"`、`quantity_precision="0"`。
- 市场切换同时保留现有币种和汇率归一化行为。
- 手动修改后的合法数值按原值提交。

提交前校验：

- `lot_size` 必须是大于 0 的十进制数。
- `quantity_precision` 必须是 0 到 12（含边界）的整数。
- 错误提示区分普通十进制字段、最小交易单位和份额小数位，避免只显示笼统错误。

## 后端安全边界

创建、编辑和替换持仓请求必须使用一致规则：

- `lot_size > 0`。
- `0 <= quantity_precision <= 12`。
- 校验失败返回结构化请求错误，不写入或部分更新持仓。
- 合法的自定义最小交易单位和份额小数位保持原值，不按市场覆盖。

该校验属于 API 写入边界。此次不新增数据库约束迁移，避免迁移过程对其他历史持仓执行推断式修正。

## 当前数据修复

在新校验部署并验证后，通过正常持仓更新 API 修复 ID 为 `9855dbdf-42fb-4dc9-853f-e08477809c93`、代码为 `563020` 的持仓：

```text
lot_size: 1 -> 100
quantity_precision: 100 -> 0
```

更新使用当前持仓版本，成功后版本只增加一次。更新前后核对以下字段完全不变：

- 持仓 ID、资产类别、代码、名称、市场和账户；
- 数量 `15000`；
- 平均成本价、成本汇率和基准汇率；
- 首选行情来源、再平衡偏好和启用状态。

不直接修改 Docker 卷，不执行清表、重建数据库或批量 SQL 更新。

## 错误处理

- 无效字段在请求进入服务层前被拒绝。
- 编辑或替换校验失败时，原持仓及其版本保持不变。
- 数据修复请求若遇到版本冲突，先重新读取数据库中的当前版本和字段，不盲目重试或覆盖并发修改。
- 部署后若持仓接口仍返回 500，停止数据修改并根据新日志重新诊断。
